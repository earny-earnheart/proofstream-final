Verify it yourself

    
A receipt is verified only when this signature check succeeds. The page treats a receipt as verified when the browser check and the server check both succeed. Anyone can repeat the check without an account.

    
    
      
  1. Fetch the receipt: GET /api/v1/receipts/<receipt id>.
    2. 
      
  2. Fetch the public key: GET /.well-known/proofstream-receipt-key.json. It is a JWK with kty OKP, crv Ed25519, x, and kid.
    3. 
      
  3. Require the receipt key_id to equal the JWK kid. kid is ed25519: plus the first 16 lowercase hex characters of SHA-256 over the raw 32-byte public key.
    4. 
      
  4. Rebuild the canonical payload as UTF-8. Join these lines with LF and do not add a trailing newline:
        
    proofstream-receipt/v1
receipt_id:<receipt_id>
fingerprint:<64 lowercase hex>
issued_at:<issued_at>
kid:<key_id>
    
      
    5. 
      
  5. Base64url-decode the signature with no padding. It is 64 bytes.
    6. 
      
  6. Ed25519-verify that signature over the payload bytes with the JWK public key. Reject the receipt if verification fails, the key id differs, or the signing key is unavailable.
    7. 
    

    
The API does not send cross-origin read access. A third party verifies from an HTTPS client, or from this page on proofstreamapp.com. POST /api/v1/receipts and POST /api/v1/fingerprints issue a receipt for {"fingerprint":"<64 hex SHA-256>"}. The file is not uploaded. If RECEIPT_SIGNING_KEY is unset, issuance returns an error and does not store an unsigned receipt.
